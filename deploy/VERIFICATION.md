## 验证中修复的问题

1. 原 MinIO 预构建镜像不能从官方仓库拉取。新增 `minio.Dockerfile`，从官方固定提交下载源码、验证 SHA256、构建镜像并保留 AGPL 许可证。来源与构建依据：[MinIO 官方说明](https://github.com/minio/minio#source-only-distribution)。
2. 用户数据库/认证服务暂时故障被当作会话过期，导致前端可能清除登录。保留内部 RPC 状态分类，依赖故障返回 503，凭据撤销仍返回 401，补充回归。
3. 接口把 UTC 时间格式化成无时区字符串，浏览器显示“8 小时前”。文件、收藏、回收站和用户完整时间字段改为 RFC3339，并适配回收站显示。
4. Vue 开发模式未注册 `extract-css` 插件，配置无条件调用导致启动失败。增加插件存在性检查。
5. 分享下载在异步请求完成后调用 `window.open`，容易被浏览器视为弹窗。改为直接访问签名附件 URL，实际下载已验证。
6. 原始 Compose 动态地址池包含网关固定 IP，Redis 先启动时占用该地址导致网关无法启动。将动态地址池限制为 `172.30.0.128/25`，保留网关 `172.30.0.2`。
7. 集成脚本失败时缺少 Compose 命令诊断。补充脱敏日志；支持完整容器模式、分片续传与基础设施故障场景。

## 2026-10-15：六项服务审计问题修复

- 文件提交事务先锁用户配额，再重新锁定校验目标目录，与删除/恢复/清理保持锁顺序；目录消失时回滚元数据并补偿清理对象。普通上传读取至多 10 MiB + 1 字节，校验实际大小及 SHA256 后才允许持久化或秒传复用。
- 认证令牌绑定 Redis 会话 ID，退出同时撤销访问和刷新权限；旧退出请求不会删除新登录会话。Redis 故障返回 503 并保留 Cookie。每账号只保留当前登录会话，升级前的无会话 ID 令牌需要重新登录。
- 初始化、合并、取消和过期清理共享带归属令牌的锁，请求执行期限短于锁期限；分片写入及删除通过 Lua 比较 UploadID，过期清理加锁后重新检查期限。并行上传分片仍受支持。
- 分享下载、预览、缩略图签名时长按剩余期限截断，不签发不足一秒的链接；取消分享不承诺立即撤销已经签发的 MinIO 直链。
- SSE 计数改为实际连接数；重复注册拒绝、重复取消不重复释放额度。
- 本地验证：全量 `go test -race ./...`、`go vet ./...`；额外设置 `GCS_TEST_REDIS_ADDR` 验证真实 Redis 的会话撤销、迟到退出、旧分片写入、条件删除和锁归属。CI 的 test 作业提供独立 Redis，避免这些测试仅在本机运行。
- 本次源码使用缓存运行时重新编译并构建七个应用容器，`microservices_smoke.py --containers --local-runtime-image cloudbox-compose-verify-storage-service:latest --migration-rehearsal` 通过。包含错误哈希不入库/不扣配额、退出后的旧令牌在各服务被拒绝、Redis 中断时退出不谎报成功，以及原有业务、依赖恢复与迁移往返检查。
- 新增目录删除竞态、旧合并不删新任务、初始化/取消遵守锁、清理重新检查过期时间、签名期限和 SSE 容量回归。未修改前端、未重跑浏览器验收；没有线上环境，无生产发布或真实数据迁移。
