# 后续功能建议（2026-10-20）

本轮只给出建议，不新增以下产品功能；AI 继续不在当前范围内。现有文件上传、下载、目录、回收站、收藏、分享、SSE、配额和账号能力已具备，接下来优先完善运行保障。

| 优先级 | 建议 | 最小验收范围 |
| --- | --- | --- |
| P0，上线前 | 指标、链路追踪与告警 | 每服务 QPS/P95/P99/错误率；数据库连接池、Redis、MinIO、Outbox 积压、RabbitMQ 死信；一次上传可通过请求/Trace ID 追到所有服务；故障产生可验证告警 |
| P0，上线前 | 定时备份与恢复工具 | 四个业务库与 MinIO 对象协调备份，异机保存；定期在空环境恢复并核对文件可下载；明确可接受的数据丢失窗口和恢复时间，迁移反向复制不能代替备份 |
| P0，上线前 | 操作审计与管理入口 | 记录登录、分享创建/撤销、永久删除、配额变更的操作者/对象/结果；管理员可禁用账号、查看配额和失败任务，权限独立且不记录令牌/密码 |
| P0/P1，视公开范围 | 文件内容安全检查 | 在现有扩展名、大小和 SHA256 校验外，增加 MIME/文件签名检查；对公开上传增加恶意文件扫描与隔离状态，明确扫描失败时的访问规则 |
| P1，数据保护 | 文件历史版本与回退 | 更新文件时保留旧版本，支持查看/恢复/删除版本，版本占用计入配额，制定保留期限；现有“分享版本号”不是文件内容版本历史 |
| P1，用户体验 | 文件夹分享、批量下载 | 明确目录分享对后续新增文件的可见性，支持流式打包下载和大小限制，避免一次性把大目录载入内存 |
| P1，账号安全 | 会话管理与可选 MFA | 展示登录设备/时间、主动撤销会话；若要支持多设备需调整当前“每账号一个会话”的规则；MFA 需含恢复码流程 |
| P2，有协作需求后 | 团队空间与角色权限 | 团队/个人配额隔离、成员邀请、只读/编辑角色、分享范围；先定义权限模型和越权测试，再加界面 |

建议实施顺序：压测暴露的连接复用问题 → 监控告警 → 备份恢复 → 审计与管理 → 文件版本/文件夹分享。邮件通知与模板可在用户有明确异步提醒需求后补充；已有 SSE 不需要仅为架构图一致而改成 WebSocket。

参考：
- [OpenTelemetry Signals](https://opentelemetry.io/docs/concepts/signals/)：指标、日志、追踪是互补的观测信号。
- [OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)：上传安全应分层校验，并按风险加入扫描和容量限制。
